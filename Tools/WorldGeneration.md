# Unified world generation

Open **Мир > Генерация мира**, or select `WorldGenerator` and use its panel button.
The default `WorldBuildSettings.asset` references the existing generation config,
biome database, POI database and voxel config. Editing the panel edits those source
assets with Unity's serialized-property/Undo support; it does not copy their knobs
into scene components.

## Workflow

- **Сгенерировать мир** runs biomes, relief and erosion, settlement hubs, roads,
  streets, POI placement/pads, map saving, ground textures, voxel preview, decor and
  linked POI instances. The order preserves the final terrain under buildings.
- **Обновить предпросмотр** reads the existing complete bake. It does not
  reroll the seed, regenerate maps or recarve streets. It also works after cancelling
  a preview build if the new maps were already saved successfully.
- **Убрать предпросмотр** releases preview meshes/decor and removes the
  preview POI hierarchy. It does not delete baked assets.
- Save the scene after the first successful run so its controller keeps the baked
  world, viewer and gameplay-pause references. The provided existing scene is not
  modified or regenerated by the code change itself.

The first successful run migrates matching old builder, streamer and POI-spawner
components in the controller's parent hierarchy. It retains the viewer reference
and replaces their generated content. Subsequent runs own a single preview root.
The old POI script remains available for unrelated legacy scenes but is not used by
the new editor or runtime workflow.

## Settings

The panel opens with the saved world's state: seed, size and save time, or why
it has to be regenerated (missing, stale generator version, incomplete). The three
actions follow, each with the reason when it is unavailable. Settings are grouped
by topic:

- **Мир** — seed (with a random button), world size, maximum height, relief
  multiplier, biome blend, terrain stamps, the relief of one selected biome
  (amplitudes in metres before the global multiplier, horizontal scales shared by
  all biomes as `WorldSize / noiseFrequency`), and vegetation density.
- **Вода** — sea level and coast, rivers, drainage valleys, main river, lake and
  pond density, water stamps, and the water, ice, bridge and culvert assets.
- **Поселения** — how many cities, towns, villages and ghost towns, the tile
  size and the regional links per settlement.
- **Детализация** — the preview's detail centre (or the scene view's pivot),
  colliders, decor rings, LOD count, near radius, control texture resolution,
  geometry budget and height cell. Terrain and POI cover the whole world;
  vegetation stays within the rings. Preview geometry is not serialized into the
  scene and is tagged `EditorOnly`; rebuild it after reopening the scene.
- **Игра** — viewer, automatic loading, behaviours paused until the world is
  ready, the standalone loading overlay and the per-frame budgets.

The source assets and the debug and import tools (ground rebake, water maps and
scene overlay, ground paint debug, LOD seam debug, stamp imports) sit in two
collapsed sections at the bottom. The memory limit estimates geometry and
collision only; it is checked in both editor and runtime. Cancellation is checked
between map stages and between preview columns/POI batches.

## Runtime

`WorldGenerator` is now the scene entry point, not the map generator. It owns a
`WorldRuntimeLoader`; all actual building/placement work is delegated to services.
The loader reads `BakedWorld.asset`, builds the voxel terrain and its colliders,
then instantiates POI in batches. Terrain stays built; vegetation follows the viewer.
It never writes generated assets or calls editor generation APIs in play mode.

`Ready`, `Progress`, `Status` and `WorldReady` can drive a custom loading screen.
Ready includes active terrain columns, in-flight collision cooking and POI. An
empty POI list is also handled; paused gameplay resumes when terrain is ready.
On failure, gameplay remains paused and the overlay reports failure instead of
starting a player over missing ground.

`BakedWorld` contains a saved config snapshot so changing world size, height range
or seed in the authoring config cannot reinterpret previously saved raw height data.
The bake is invalidated before generated files are overwritten and becomes usable
again only after maps/material/config have been saved consistently. Cancellation
before saving leaves the old bake untouched; cancellation during preview creation
keeps the old preview and any newly completed bake. Asset writes are not undone by
scene Undo. Preview POI transforms are previews, not edits to `PoiPlacement.asset`.

Generated PNGs and raw height data are written to a unique hidden temporary file
beside the destination, then replaced without truncating the existing asset. This
avoids Win32 error 1224 when an imported file still has a memory-mapped reader.
The `.meta` file is left unchanged. Short sharing conflicts receive bounded retries;
a persistent lock aborts the save rather than falling back to destructive truncation.
Each file is replaced separately; the complete bake still uses its validity marker.

## Checks

From the repository root:

```text
dotnet build Tools/UnityCompileCheck/UnityCompileCheck.BenchmarksEditor.csproj --no-restore
dotnet build Tools/UnityTestCompileCheck/UnityTestCompileCheck.csproj --no-restore
```

World generation compiles into its own assemblies: `Dustborn.WorldGen`
(`Scripts/Gameplay/Service/WorldService`), `Dustborn.WorldGen.Editor` (its
`Editor/` folder), `Dustborn.WorldGen.Benchmarks` and
`Dustborn.WorldGen.Benchmarks.Editor` (`Benchmarks/WorldGeneration`), and
`Dustborn.Utils` (`Scripts/Utils`). `UnityCompileCheck` has one project per
assembly with the same references, so building `BenchmarksEditor` builds all of
them and a reference across an asmdef boundary fails here as it would in Unity.
The folder holds several projects, so `dotnet build Tools/UnityCompileCheck`
alone fails with MSB1050. The tests reference these assemblies directly;
`HeadlessCheck --quality` compares every `[Quality]` field of the world assets
with its code default, as `WorldQualityTests` does in the editor.

From `Tools/HeadlessCheck`:

```text
dotnet run --project HeadlessCheck.csproj -- --pipeline-smoke
dotnet run --project HeadlessCheck.csproj -- --asset-write-smoke
```

The smoke check uses a small in-memory test world and does not overwrite project
maps. It covers stage order/progress, repeatability, roads/POI, cancellation followed
by reuse, seed changes and build budgets. It does not validate Unity rendering,
prefab Undo, scene serialization or interactive loading; check those in the editor.

The asset-write check uses temporary files only. On Windows it reproduces error 1224
with the previous writer and verifies replacement while the mapped reader remains
open, preservation of GUID metadata, shorter replacements, rejection of exclusive
reader locks without data loss, and cleanup of temporary files.

## Water and drainage (generator version 4)

Rivers are no longer strung together from whatever hollows the noise relief
leaves. `Hydrate` runs, in order: the arid lift, the coast, **drainage valleys**,
hydrology, river carving, water stamps, shore regions.

- `DrainageValleys` solves drainage on a 32 m grid from ocean-connected outlets,
  fits a monotone floor per valley (isotonic regression with a minimum grade, a
  cut limit `ValleyMaxCut` and a fill limit `ValleyMaxFill`; a deeper hollow is
  left open as a lake) and cuts connected valleys into the relief wherever the
  runoff-weighted catchment reaches `RiverStartArea`.
- Dry land takes no river. Biomes whose `Water` is `None`, plus a 48 m margin,
  are outlets of the hydrology Priority-Flood, so wet water never routes through
  them, but an end at dry land is not a terminal: `ResolveEnds` cuts such a
  course back to its last lake or drops it, and `ExtendToWater` stops at dry
  cells. No river runs up to a desert and fades out, and no river, lake or pond
  lies inside a desert or a burnt forest. The sea along a dry coast stays.
  `DryBiomeRunoff` only weights the drainage valleys, which may cross dry land
  as dry wadis. The catchments beside dry land keep only the rivers that reach
  the sea or a lake, so a seed whose big river used to die in a desert has
  noticeably less river length.
- The sea is only the water connected to the world edge, in hydrology as well
  as in the meshes: a river that drops to sea level over a lifted inland plain
  is not in the sea and is not marked submerged there.
- Rivers are traced as main stems from each mouth upstream along the largest
  catchment; tributaries branch off them. The main river is the stem that runs
  farthest through `MainRiver` biomes and is only drawn wider; if no stem is
  long enough the log says why and the world has no main river.
- Every river records its source (headwater with the catchment evidence of its
  channel head, lake outlet, boundary, distributary), its terminal (sea, lake,
  junction, border) and its parent. `WaterMap` version 5 serializes them
  together with the dry mask.
- A river reaches the level of what it flows into before it gets there: the last
  `max(12 m, 2 widths)` before standing water or a trunk are a backwater at that
  level, and the riffle moves upstream. The standing body is walled off by any
  river segment with either end above its level, and the ribbon is clipped only
  where the body really covers it, so a mouth has neither a step nor a double
  surface. Tributaries are re-attached to their trunk's final level
  (`Hydrology.MeetTrunks`) after the trunk is reshaped.
- The channel has a flat bed over the inner quarter of its width, a Hermite wall
  that meets the waterline at 0.45 (24°, under the cliff paint) and continues
  into a lip of the same slope, so the waterline is where the terrain crosses the
  water plane and not a crease. The ribbon reaches `WaterMeshes.RIBBON_PAD`
  (0.5 m) past the nominal width under that lip, and `WaterMap.TryRiver` covers
  the same width. Sources are 1.2 m deep. Along rivers the voxel rings are
  refined down to `ring - 4` (`RIVER_LOD_SLACK`), never coarser than 2 m.
- The sea is only the water connected to the world edge (sand bars under
  `WaterMap.LAGOON_BAR` do not separate a lagoon); inland ground below sea
  level is not sea.
- River levels do not move after the channel is cut. The shore pass settles
  submerged points to the water they lie in and reopens uncovered ones;
  `WorldMapPipeline.SettleWater` compares levels, loose ends and lake levels
  before and after it and, if anything moved, carves again from the uncarved
  relief with the settled levels (two or three rounds on the test seeds, four
  at most). A lake floods from its hydrology basin in every pass, plus the
  channel of a river submerged in it, so a wide river through a lake leaves no
  dry trench along the lake's edge.
- Nothing built later cuts into standing water: a road whose shoulder comes
  within 8 m of a lake, pond or the sea is raised to its level + 0.5 m, and a
  settlement tile with a lake or pond under it or its pad skirt is refused.

### Rebuild

The water map format and the terrain both changed, so a bake made before this
version is refused (`BakedWorld.GENERATOR_VERSION` 5; the panel says the saved
world is stale, the runtime throws). Open **Мир > Генерация мира** and press
**Сгенерировать мир** once. Raw height caches made by the harness from older
relief code stay valid only for relief; any water result must be regenerated.

### Water checks

From `Tools/HeadlessCheck` (build first with `dotnet build -c Release`):

```text
bin/Release/net10.0/HeadlessCheck.exe --water
bin/Release/net10.0/HeadlessCheck.exe --water-fixtures
bin/Release/net10.0/HeadlessCheck.exe --water-audit --generate --stamped --strict --raw-cache raw.bytes Seed=1613419011
bin/Release/net10.0/HeadlessCheck.exe --water-audit --pipeline --stamped --strict Seed=1613419011
```

`--strict` fails the process (exit code 1) on the river graph contract
(`WaterContract`: justified sources and terminals, attached junctions, no parent
cycles, no rising surface, no lost flow) and on local maxima rather than shares
of the total area: the largest hole, hanging, edge-cliff (ground beside the
water mesh more than 0.3 m under it), z-fighting and stacked-water patch
(16 m²), hanging height (0.3 m), water hidden by the near LOD rings (32 m²),
trench depth (8 m), mouth gaps, T-junctions, inclined planes (40 m), any river
ending within 24 m of dry land, plus a floor on river length, river count and
standing bodies so deleting water cannot pass. With `--generate` it also replays
`RiverCarver.Restore` over the result and prints how much channel was cut for
levels that changed afterwards (`русло врезано не по итоговому уровню`).
`--water-fixtures` runs nine small adversarial worlds through the same
contract. `--events` prints what hydrology removed, captured or merged and why;
`--valley-at x z` lists the drainage valley points near a spot. The floors on
river length, river count and bodies are per km² of land outside dry biomes.

The harness generates the same world as Unity for a seed: `Stubs.cs` reproduces
`Unity.Mathematics.Random` bit for bit (the state is returned before the
xorshift step, the constructor advances once, `NextFloat` uses the mantissa).
Before that fix every harness measurement ran on a different biome layout.
`--water-audit --pipeline --stamped --compare-bake` generates the whole world and
prints how far its heights are from `Generated/HeightMap.bytes`; with the water
stamps attached (`--stamped`, as the game does) 99.6 % of samples agree within
5 cm, the rest differ where road routing diverges.
