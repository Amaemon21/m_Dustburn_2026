# Unified world generation

Open **Мир > Генерация мира**, or select `WorldGenerator` and use its panel button.
The default `WorldBuildSettings.asset` references the existing generation config,
biome database, POI database and voxel config. Editing the panel edits those source
assets with Unity's serialized-property/Undo support; it does not copy their knobs
into scene components.

## Workflow

- **Сгенерировать мир** runs biomes, relief and erosion, settlement hubs, roads,
  streets, POI placement/pads, map saving, ground textures, voxel preview, decor and
  linked POI instances. The order preserves the final terrain under buildings.
- **Обновить только предпросмотр** reads the existing complete bake. It does not
  reroll the seed, regenerate maps or recarve streets. It also works after cancelling
  a preview build if the new maps were already saved successfully.
- **Убрать предпросмотр из сцены** releases preview meshes/decor and removes the
  preview POI hierarchy. It does not delete baked assets.
- Save the scene after the first successful run so its controller keeps the baked
  world, viewer and gameplay-pause references. The provided existing scene is not
  modified or regenerated by the code change itself.

The first successful run migrates matching old builder, streamer and POI-spawner
components in the controller's parent hierarchy. It retains the viewer reference
and replaces their generated content. Subsequent runs own a single preview root.
The old POI script remains available for unrelated legacy scenes but is not used by
the new editor or runtime workflow.

## Settings

**Основное** contains world size, one deterministic world seed, a biome selector,
base height, hill amplitude/scale, detail amplitude/scale and grass density.
Base height and amplitudes edit the selected biome. Amplitudes are shown in metres
before the global relief multiplier. The two horizontal scales are shared across
biomes and display `WorldSize / noiseFrequency` in metres.

**Редактор** controls the preview's detail centre, colliders and geometry budget.
Terrain and POI cover the whole world; vegetation stays within the configured LOD
rings. This intentionally avoids creating an entire 8 km world of grass at once.
The preview terrain is transient: meshes/decor are not serialized into the scene.
Rebuild the preview after reopening the scene; linked POI instances remain saved.
The complete preview hierarchy is tagged `EditorOnly` and excluded from builds.

**В игре** controls the viewer, automatic loading, optional loading overlay,
gameplay behaviours suspended during loading and POI batching. The existing
`PlayerController` is registered automatically when the viewer is migrated or
assigned. Other movement/spawn scripts can be added explicitly. An originally
disabled behaviour is never enabled by the loader.

Extra quality, settlement, water and source-asset settings stay in a foldout.
The memory limit estimates geometry and collision only, not the height/biome maps,
textures or vegetation. It is checked in both editor and runtime. Large native
generation stages remain synchronous; cancellation is checked between map stages
and between preview columns/POI batches, not inside an already-running Burst job.

## Runtime

`WorldGenerator` is now the scene entry point, not the map generator. It owns a
`WorldRuntimeLoader`; all actual building/placement work is delegated to services.
The loader reads `BakedWorld.asset`, builds the voxel terrain and its colliders,
then instantiates POI in batches. Terrain stays built; vegetation follows the viewer.
It never writes generated assets or calls editor generation APIs in play mode.

`Ready`, `Progress`, `Status` and `WorldReady` can drive a custom loading screen.
Ready includes active terrain columns, in-flight collision cooking and POI. An
empty POI list is also handled; paused gameplay resumes when terrain is ready.
On failure, gameplay remains paused and the overlay reports failure instead of
starting a player over missing ground.

`BakedWorld` contains a saved config snapshot so changing world size, height range
or seed in the authoring config cannot reinterpret previously saved raw height data.
The bake is invalidated before generated files are overwritten and becomes usable
again only after maps/material/config have been saved consistently. Cancellation
before saving leaves the old bake untouched; cancellation during preview creation
keeps the old preview and any newly completed bake. Asset writes are not undone by
scene Undo. Preview POI transforms are previews, not edits to `PoiPlacement.asset`.

Generated PNGs and raw height data are written to a unique hidden temporary file
beside the destination, then replaced without truncating the existing asset. This
avoids Win32 error 1224 when an imported file still has a memory-mapped reader.
The `.meta` file is left unchanged. Short sharing conflicts receive bounded retries;
a persistent lock aborts the save rather than falling back to destructive truncation.
Each file is replaced separately; the complete bake still uses its validity marker.

## Checks

From the repository root:

```text
dotnet build Tools/UnityCompileCheck --no-restore
dotnet build Tools/UnityCompileCheck --no-restore -p:UnityEditorBuild=false
```

From `Tools/HeadlessCheck`:

```text
dotnet run --project HeadlessCheck.csproj -- --pipeline-smoke
dotnet run --project HeadlessCheck.csproj -- --asset-write-smoke
```

The smoke check uses a small in-memory test world and does not overwrite project
maps. It covers stage order/progress, repeatability, roads/POI, cancellation followed
by reuse, seed changes and build budgets. It does not validate Unity rendering,
prefab Undo, scene serialization or interactive loading; check those in the editor.

The asset-write check uses temporary files only. On Windows it reproduces error 1224
with the previous writer and verifies replacement while the mapped reader remains
open, preservation of GUID metadata, shorter replacements, rejection of exclusive
reader locks without data loss, and cleanup of temporary files.
